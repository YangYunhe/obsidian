# OAuth 2 的定义与核心角色

> 对应书中 **1.1 节**。一句话：OAuth 2 是一套**委派授权**的标准协议——第三方应用在用户授权后拿到一枚**访问令牌（access_token）**，凭令牌**代表用户**访问其资源。

## 一、先用一个类比理解

把 OAuth 2 想成**发临时门禁卡**：

| 现实世界 | OAuth 2 |
| --- | --- |
| 房主 | **资源所有者** |
| 房子与屋里的财物 | **资源服务器** |
| 请来打扫的保洁公司 | **第三方应用**（应用程序） |
| 小区前台：核对身份、发门禁卡 | **授权服务器** |
| 临时门禁卡 | **access_token** |

保洁公司不需要拿到房主的钥匙（= 用户密码），只要前台核验后发的临时卡（= 令牌），就能在**限定范围、限定时间**内进出。

## 二、官方定义拆成三句话

1. **它是什么**：OAuth 2 是一个标准的**授权协议**。
2. **怎么授权**：采用**委派代理**的方式——资源所有者把一部分权限委托给第三方应用。
3. **凭什么访问**：授权服务器颁发 **access_token**，第三方应用持令牌代表用户访问资源。

> 最核心的一点：第三方应用**始终拿不到用户密码**，只拿到「有范围、有期限、可撤销」的令牌。

## 三、四种角色

| 角色 | 英文 | 通俗解释 | 例子 |
| --- | --- | --- | --- |
| **资源所有者** | Resource Owner | 资源的主人，通常是自然人（也可能是应用） | 你本人 |
| **资源服务器** | Resource Server | 存储受保护资源的地方 | 存有你昵称、头像、订单的服务器 |
| **应用程序** | Application / Client | 想访问你资源的那个程序 | 第三方 Web / 移动端 / 桌面应用 |
| **授权服务器** | Authorization Server | 征得你同意后，给应用颁发令牌 | 开放平台的授权服务 |

**记忆顺序**：谁的东西（所有者）→ 东西放在哪（资源服务器）→ 谁来用（应用）→ 谁发证（授权服务器）。

## 四、放到「开放平台」语境里

### 4.1 开放平台在做什么

开放平台的核心，是把**开放系统**（平台背后的业务系统）的**功能**和**数据**开放给**第三方应用**，实现能力共建。

- 有的功能和数据**与用户无关**，比如公开目录、天气信息；
- 有的则**与用户强相关**，比如个人信息、订单记录。

### 4.2 两种开放场景

| 场景 | 参与方 | 需要用户授权吗 | 说明 |
| --- | --- | --- | --- |
| **场景一** | 第三方应用 + 开放平台 | 否 | 平台只验证第三方应用的身份，明确开放范围 |
| **场景二** | 第三方应用 + 开放平台 + 开放系统用户 | **是** | 平台先验证应用权限，**再由用户授权**，之后才开放对应功能与数据 |

两种场景都要把特定功能/数据开放给第三方，所以 OAuth 2 定义了完整的**请求—授予**交互流程来支撑。

### 4.3 三个关键角色

| 角色 | 说明 |
| --- | --- |
| **开放平台** | 服务于开放系统，是开放系统与第三方应用之间的沟通桥梁 |
| **开放系统的用户** | 使用开放系统功能的人；其相关数据与操作能力归开放系统所有 |
| **第三方应用** | 开放平台企业之外的公司开发的应用；在平台申请账号后对接 |

> 为什么必须有授权？因为第三方应用与开放平台**不在同一家公司**，无法共享账号体系，只能用 OAuth 2 建立信任。

### 4.4 两个关键信息

| 信息 | 含义 | 在 OAuth 2 中的载体 |
| --- | --- | --- |
| **功能** | 开放系统提供的 API，通常以**权限包**形式提供；第三方申请、平台运营审核后获得 | 权限包与 **scope** 对应（一个 scope 可对应一个或多个权限包） |
| **数据** | 用户在开放系统中的信息：昵称、头像、手机号、住址、业务信息等 | 用 **scope** 表示获取范围；一次可申请/授予多个 scope |

一句话记住：**功能 = 能调用哪些 API；数据 = 能读到哪些用户信息；两者都用 scope 圈定范围。**

## 五、把整节串起来

```text
用户（资源所有者） ──授权──▶ 授权服务器
                                   │ 颁发 access_token
                                   ▼
第三方应用（应用程序） ──持令牌──▶ 资源服务器（受保护资源）
        ▲
        └── 在开放平台注册、申请权限包 → 对应 scope
```

- **场景一**：跳过「用户授权」，平台直接校验应用身份与权限包；
- **场景二**：多一步用户同意；令牌代表的正是「这个用户授权给这个应用的范围」。

## 六、易混点小抄

- **scope 是范围，权限包是产品化封装**：申请时看权限包，协议里传 scope。
- **access_token 不是密码**：它有范围（scope）、有期限，也可被撤销。
- **四种角色**（官方定义）与**开放平台三角色**（业务视角）可以对应起来看：资源所有者≈开放系统的用户，应用程序≈第三方应用，授权服务器≈开放平台的授权服务。
- **授权 ≠ 认证**：本节讲「能不能访问」；「你是谁」属于认证，是后续内容。
